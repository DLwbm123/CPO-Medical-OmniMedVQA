# Four-rank ZeRO-3 compressed recovery control

The actual installed DeepSpeed 0.17.5 backend saved and reloaded model/Adam shards through the experimental streaming gzip checkpoint engine on four GPUs. The fixture was a tiny shared embedding/head model with dropout, seed 314 and rank-specific RNG seed 700+rank. It performed update 0, saved the checkpoint and rank-local RNG, then compared an uninterrupted update 1 against a fresh engine loading that checkpoint, restoring rank RNG and performing the same update 1.

All four ranks exited zero. The global maximum difference in FP32 master-parameter partitions was 0, and the global maximum Adam slot-state difference was 0; restored optimizer update count was 2. All 12 model/optimizer/RNG state files were gzip streams. Their combined size was 48,049 bytes. This is not a realistic medical-model compression-ratio measurement or evidence that a full medical checkpoint fits the 50GB budget.

The first attempt saved compressed shards but failed in the measurement harness: ZeRO-3 clears its underlying Adam param groups between steps, making direct raw `optimizer.state_dict()` invalid. The repair compared actual Adam slot states in the known FP32 partition order instead. The model, stochastic sequence, criterion (global max error <=1e-6), original 900-second clock and 1GB output limit remained unchanged. First-attempt logs and shards are retained. Total supervised elapsed time including repair was about 64.6 seconds.

Static review found standard same-world-size non-universal ZeRO-3 loads use the configured checkpoint engine. Universal checkpoint loaders contain direct torch.load calls and are outside this codec's supported scope. The code is explicit opt-in; a caller must confirm all its readers use the codec. Streaming saves create no raw checkpoint temporary file, enforce a compressed file cap, and preserve the prior file if a replacement fails. CPU tests additionally cover exact optimizer/view-sharing roundtrip and budget failure preserving the previous checkpoint.

This completes only a backend-level recovery check on the tiny fixture. Real Qwen/Adam compression rate, safe full-size output headroom, Trainer sampler/rollout handling and PACT memory/controller/card-cost recovery remain unvalidated. Nothing here establishes PACT effectiveness. Medical weights, private images, questions, references and memories were not accessed by this control and are not included.
